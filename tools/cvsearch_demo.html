How this works, and the test scores

The CVs are the test split of the Djinni recruitment dataset (anonymized by its authors, MIT). Keywords are mined from the skill lists of 168k other Djinni CVs; the implication graph comes from their co-occurrence (“whoever names Qt almost always names C++”). No LLM, no labels, no taxonomy. The embedding models are trained on that graph.

Search reads the skills your text names, longest match first (“Spring Boot developer” is Spring Boot), using the same keyword rules as the notebook; words a third of the CVs use, like “developer”, don't count. It lists the CVs that name the skill first; the rest are a fallback ranked by their best keywords: in “Who has it”, keywords that imply the skill; in “What it implies”, keywords the skill implies, with the CVs that also look most like the skill first. Results are precomputed for the most named skills; seed 0 of each model.

The Primary Keyword is what the candidate picked as their main stack on the platform. Nothing in the pipeline reads it; it is shown to check results, with ✓ when it matches a query for one of the 18 evaluated technologies.
